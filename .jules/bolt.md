## 2024-05-16 - [Frontend Performance: Caching getBoundingClientRect in Animation Loops]
**Learning:** Frequent calls to `getBoundingClientRect()` inside `requestAnimationFrame` loops or scroll handlers (like in `MagneticLetters`, `MobileTouchRepel`, and `ParallaxLayers`) cause significant layout thrashing and forced synchronous layouts, degrading rendering performance.
**Action:** Always pre-calculate and cache document-relative element positions during initialization (`init()`). Update this cache on window resize events and after custom fonts load (using `document.fonts.ready.then()`). During active animations (`animate()`, `update()`, etc.), calculate viewport-relative positions using the cached document coordinates minus the current scroll offset (`window.scrollX` / `window.scrollY`) instead of directly querying the DOM.
## 2026-03-22 - [Frontend Performance: Caching getBoundingClientRect and Window dimensions in Scroll and Intersection Observers]
**Learning:** Querying `document.documentElement.scrollHeight` and `window.innerHeight` continuously inside `requestAnimationFrame`, scroll loops, or `IntersectionObserver` handlers causes unnecessary layout checks and can lead to layout thrashing, reducing page performance and responsiveness during scrolling.
**Action:** Always pre-calculate and cache document and window dimensions during initialization (`init()`). Automatically re-calculate these values globally via the window `resize` handler and a `ResizeObserver` applied to `document.documentElement` to accurately handle layout changes while remaining efficient. Use these cached properties during updates instead of directly accessing the DOM or window.
